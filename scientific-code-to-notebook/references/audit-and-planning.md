# 源码审计与改造计划

## 不可省略的检查

| 维度 | 检查内容 | 记录方式 |
|---|---|---|
| 数据 | 数据集版本/哈希、实际范围、样本层级、缺失定义、测量单位 | input_manifest.csv |
| 入口 | CLI、脚本、Notebook、批任务、隐式全局变量 | entrypoint_map.md |
| 算法 | 名称、公式、来源、脚本路径/行号、所需数据、约束 | method_registry.csv |
| 参数 | 默认值、合法区间、论文值/研究适配值 | config.yaml 与方法卡 |
| 输出 | 图、表、中间缓存、固定顺序与字段定义；**标识符字段的变换规则**（后缀剥除/大小写/命名映射）逐字段登记 | output_map.md |
| 测试 | 文献基准、作者代码输出、已有回归值、QC 缺失 | validation_matrix.csv |
| 环境 | 语言、依赖包版本、编译器/BLAS、OS、seed | environment manifest |

## 改造前顺序

1. 确认数据是否具有使用授权、是否含敏感内容，避免将原始隐私数据写入示例/日志。
2. 确定完整科学流程：数据加载 → 清理 → 算法 → 聚合 → 推断 → 制图。
3. 找出“稳定共享基础设施”与“应该在 Notebook 显式展示的关键科学算法”。
4. 冻结一份原始结果，用数据集与代码版本标记。
5. 建立映射表 `original_file:line/function → notebook:cell`；追踪无法迁移的分支。
6. 枚举原实现输出的全部字段（含标识符/字符串字段及其变换规则），逐字段登记"已移植/已知差异"——数值指标之外的字段（如 ID 生成规则）最易被遗漏。
7. 标注有多种文献定义的指标：不要因为名字一样而混用。
8. 明确科学计算和工程重构之间的界限；问题单列 issue，不静默更改科学结论。

## 阻断条件

- 找不到方法来源或作者算法含关键未公布环节：不得声称“忠实复现”。
- 缺少必要校准、标定、分组或观测元数据：输出 QC 或待办，不制造替代值。
- 原版无法运行：尽可能利用保留输出/测试验证局部行为；说明验证范围不足。
- 论文定义与原代码不一致：同时保留原实现及差异记录，建议由用户决定是否进行科学性修正。
